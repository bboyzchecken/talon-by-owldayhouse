# SPEC.md — รายละเอียดเชิงลึก (UP Docs)

เอกสารนี้ขยายจาก `CLAUDE.md` — ใช้คู่กับ `templates.json` (เนื้อความ) และ `reference.json` (ค่ากลาง)
ทุกอย่างในนี้ **แกะจากไฟล์ .docx ต้นฉบับจริง** (โฟลเดอร์ `reference-docx/`) ไม่ใช่สมมติ

---

## 1. Data model (สคีมาเดียว กรอกครั้งเดียวเติมทุกจุด)

```js
const state = {
  docType: 'request',           // request|acceptance|sendoff|thanks|extracurricular|cancel
  mode: 'internship',           // internship|coop|cwie (เฉพาะใบที่มีโหมด)
  paper: 'letter',              // letter|a4
  docNo: '',                    // หลัง "อว ๗๓๒๕/"
  date: { month:'', yearBE:'', full:false, day:'' },
  recipient: '',                // เรียน...
  org: '',                      // สถานประกอบการ (ใช้ซ้ำหลายจุด+ใบตอบรับ)
  courseCode:'', program:'บริหารธุรกิจบัณฑิต', major:'', semester:'ปลาย', yearEduBE:'',
  dateStart:'', dateEnd:'', replyBy:'',
  yearLevel:'',                 // นอกหลักสูตร
  ref:{ docNo:'', date:'' },    // ยกเลิก
  cancelReason: DEFAULT_CANCEL_REASON,
  students: [ {name:'', phone:''} ],   // 1–4 คน
  signerId: 's1'
};
```

**กติกาสำคัญ**
- `attachCount` = `students.length` (auto, เลขไทย)
- `studentCount` = `students.length` (auto, เลขไทย)
- โครงจดหมาย: `students.length === 1` → ใช้ `body.single` · `>= 2` → `body.many`
- ฟิลด์ที่ต้นฉบับ "ใช้ 2 ครั้ง" (org, major, ชื่อนิสิต, วันที่) = ผูกค่าเดียว เรนเดอร์ทุก slot รวมถึงใบตอบรับ

## 3. โหมด ฝึกงาน/สหกิจ/CWIE — ต่างแค่ "วลี"

สหกิจกับ CWIE เกือบเหมือนกัน ต่างที่คำอธิบายกิจกรรม ทำ template เดียวสลับตัวแปร (ดู `templates.json` → `modeText`) ตัวอย่างจุดที่ต่าง:

| จุด | ฝึกงาน | สหกิจ | CWIE |
|---|---|---|---|
| เรื่อง | ...เข้าฝึกงาน | ...เข้าปฏิบัติสหกิจศึกษา | ...ปฏิบัติงานสหกิจศึกษาและการศึกษาเชิงบูรณาการกับการทำงาน (CWIE) |
| กิจกรรม | เข้ารับการฝึกงาน | เข้ารับปฏิบัติสหกิจศึกษา | เข้ารับปฏิบัติงานสหกิจศึกษาและการศึกษาเชิงบูรณาการกับการทำงาน |
| คำวิชา | การฝึกงาน | สหกิจศึกษา | รายวิชาสหกิจศึกษาและการศึกษาเชิงบูรณาการ |

## 4. การจัดหน้า (ค่าเป๊ะจาก .docx)

- **กระดาษ:** Letter 21.59×27.94 ซม. (ทุกใบ ยกเว้นนอกหลักสูตร = A4 — รอยืนยัน)
- **ฟอนต์:** TH Sarabun ๙ 16pt · หัวใบตอบรับ 22pt · line-spacing 1.0
- **Margin จดหมาย:** L3.0 R2.0 T1.5 B1.0 ซม. · **ใบตอบรับ:** L1.75 R1.6 T1.5 B1.25 ซม.
- **ย่อหน้าเนื้อความ:** `text-align:justify` (แบบไทย) · เยื้องบรรทัดแรก 2.54 ซม. · space-before 6pt (บางย่อหน้า 12pt)
- **ลิสต์นิสิต:** เยื้องซ้าย 1.27 ซม. · เลขไทย ๑. ๒. ๓. ๔.
- **หัวจดหมาย:** 2 คอลัมน์ — ซ้าย `ที่ อว ๗๓๒๕/{docNo}` · ขวา 3 บรรทัด (มหาวิทยาลัยพะเยา / ตำบลแม่กา อำเภอเมืองพะเยา / จังหวัดพะเยา ๕๖๐๐๐) ชิดค่อนขวา
- **วันที่:** บรรทัดถัดมา จัดกึ่งกลาง
- **ผู้ลงนาม:** จัดกึ่งกลางค่อนขวา — `(ชื่อ)` แล้วตามด้วยบรรทัดตำแหน่ง
- **footer** (ใบขอ/ส่งตัว): มุมซ้ายล่าง 3 บรรทัด (ชื่อคณะ/โทร/โทรสาร)

> CSS แนะนำ: `@page{size:letter;margin:0}` แล้วให้ `.page` ทำ padding เป็น ซม.จริง (เหมือน owl-docs-generator.html ที่ทำ 13/15mm)

## 5. เลขไทย + วันที่ (ต้องมี — ต้นฉบับใช้เลขไทยล้วน)

```
toThaiNum('2569') -> '๒๕๖๙'   // 0123456789 -> ๐๑๒๓๔๕๖๗๘๙
```
- ผู้ใช้พิมพ์อารบิก ระบบแปลงเลขไทยตอนเรนเดอร์ (วันที่/เบอร์/จำนวน)
- วันที่ default = `{เดือนไทย} {ปีพ.ศ.ไทย}` เช่น "กรกฎาคม ๒๕๖๙" · option เต็มวัน = "๓ กรกฎาคม ๒๕๖๙"
- ปีที่ผู้ใช้กรอกเป็น พ.ศ. อยู่แล้ว (ต้นฉบับใช้ ๒๕๖๙) — ไม่ต้องบวก 543 เว้นแต่จะให้กรอก ค.ศ.

## 6. โครงสร้างเนื้อความ

ใน `templates.json` แต่ละ document มี `body` เป็น array ของ block ตามลำดับ พร้อม token
- Block types: `subject` (เรื่อง), `recipient` (เรียน), `attach` (สิ่งที่ส่งมาด้วย), `para` (ย่อหน้า), `list_numbered` (นิสิต+เบอร์), `list_names` (ชื่ออย่างเดียว), `title` (หัวฟอร์ม), `field` (ช่องกรอกในฟอร์ม), `signline` (ช่องเซ็น), `closing`, `signer`
- Chrome ร่วม (header/date/footer) อยู่ใน `_shared_chrome`
- Token: `{{key}}` · `{{mode.x}}` วลีตามโหมด · `{{student.1.name}}` คนที่ 1 · list ใช้ `item` ต่อบรรทัด

**ตัวอย่าง single vs many (ใบขอ):**
- single: "...จึงขอความอนุเคราะห์ให้ **{{student.1.name}}** นิสิตสาขาวิชา{{major}} หมายเลขโทรศัพท์ {{student.1.phone}} {{mode.activity}} ณ {{org}}..."
- many: "...จึงขอความอนุเคราะห์ให้ **นิสิต**{{mode.activity}} ณ {{org}}... โดยนิสิตจำนวน {{studentCount}} ราย มีดังนี้" + list ๑./๒./๓./๔.

## 7. เอกสารแนบพิมพ์พร้อมกัน (โจทย์ข้อ 2)

- เมื่อ docType = `request` → หลังหน้าจดหมาย ใส่ **page-break** แล้วเรนเดอร์ `acceptance` (โหมดตรงกัน: ฝึกงาน→internship, สหกิจ/CWIE→coop)
- ใบตอบรับดึง `org / major / students(ชื่อ) / dateStart / dateEnd` จาก state เดียวกัน (ไม่กรอกซ้ำ) ช่องที่บริษัทต้องเขียนเอง (ข้าพเจ้า/ตำแหน่ง/ที่ตั้ง/โทร/ลงชื่อ) เว้นเส้นประ
- ผู้ใช้เลือกได้ว่าจะพิมพ์ "ใบขอ+แนบ" หรือ "ใบขออย่างเดียว" (checkbox)

## 8. ระบบผู้ลงนาม (โจทย์ข้อ 8)

- dropdown จาก `reference.signers` (ตอนนี้มี s1 จริง + s2–s6 `__รอข้อมูล__`)
- แต่ละคน: `name`, `title_lines[]`, `acting_for_dean`
- ถ้า `acting_for_dean:true` → ท้ายมี "...ปฏิบัติการแทน / คณบดีคณะบริหารธุรกิจและนิเทศศาสตร์" (แบบ s1)
- ถ้าคณบดีเซ็นเอง → โชว์ตำแหน่งคณบดีตรง ไม่มี "ปฏิบัติการแทน"
- **รอเจ้าของ:** ชื่อ+ตำแหน่ง 5 คน และใครเซ็นตรง/ใครปฏิบัติการแทน (DECISIONS ข้อ 4)

## 9. หมายเหตุความถูกต้องของต้นฉบับ (typo)

ต้นฉบับมีจุดที่น่าจะพิมพ์พลาด — **อย่าแก้เงียบ ๆ** ให้ถามเจ้าของ (DECISIONS ข้อ 6):
- "ด้วยด้วย" (นอกหลักสูตร) — ซ้ำคำ
- "สถานประกอบการณ์" — น่าจะ "สถานประกอบการ"
- "ทำให้นิสิตไม่ทราบเข้ารับการฝึกงานได้" (ยกเลิก) — น่าจะ "ไม่สามารถ"

ใน `templates.json` ผมใส่เวอร์ชันที่แก้แล้วไว้ + คอมเมนต์ระบุของเดิม รอ confirm

## 10. เทสต์เชคลิสต์ (ก่อนส่ง demo)

- [ ] ใบตอบรับตามหลังถูกหน้า + ข้อมูลตรง
- [ ] เลขไทย/พ.ศ. ถูก · จำนวนแนบ = จำนวนนิสิต
- [ ] margin/ฟอนต์/ย่อหน้า เทียบ .docx แล้วตา
- [ ] บล็อกผู้ลงนามสลับถูกตามคน
- [ ] พิมพ์ PDF ออกมาสวย ไม่มีขอบเพี้ยน

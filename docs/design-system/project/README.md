ระบบนี้กำหนดหน้าตาของ Owl Day House ในฐานะทีมสร้างสรรค์ที่ทำได้ทั้งระบบ หน้างานอีเวนต์ และการตลาด หลักคือพื้นขาวกว้าง ตัวอักษรใหญ่ ภาพคุณภาพสูง และสีแบรนด์เฉพาะจุดสำคัญ

## ตำแหน่งของแบรนด์

- จัดบริการเป็น 3 เสา: **Build** (สร้างระบบ), **Activate** (สร้างกระแส), **Grow** (สร้างลูกค้า)
- เขียนหน้าการตลาดโดยไม่มีราคาและไม่มีชื่อแพ็กเกจ ทุกปุ่มพาไปคุยผ่านอีเมล Messenger, LINE หรือโทรศัพท์
- ห้ามทำฟอร์มบนเว็บการตลาด เว็บเป็น static ทั้งหมด

## น้ำเสียงและการเขียน

- เขียนภาษาไทยเป็นหลัก เรียกตัวเองว่า "เรา" และเรียกลูกค้าว่า "คุณ" หรือ "แบรนด์"
- เขียนสั้น มั่นใจ บอกสิ่งที่ทำได้ตรง ๆ ไม่ใช้คำเร่งขาย ไม่ใช้อีโมจิ
- ใช้ภาษาอังกฤษเฉพาะคำใหญ่บน Hero, ชื่อเสา และป้าย `mono`

| ใช้ | เลิกใช้ |
| --- | --- |
| "คุยโปรเจกต์", "มาคุยกัน" | "เริ่มเลย ฿3,900", "ทักเราเลย" |
| "ทีมเดียว ตั้งแต่ระบบถึงหน้างาน" | "เสร็จไว ดูแลต่อ", "เสร็จใน 5 วัน" |
| "ซอฟต์แวร์เบื้องหลังทุกบริการ", "เปิดให้เชื่อมต่อ ไม่ปิดกั้น" | "ต่อ AI ได้", "เว็บที่สร้างโดย AI", "AI ทำให้" |
| "จัดทำร่วมกับพาร์ตเนอร์" | การอ้างว่างาน Social Listening เป็นของเราเอง |

- เล่าเรื่อง MCP และการเชื่อมต่อ AI ที่หน้าเครื่องมือเป็นหลัก ห้ามติดเป็นป้ายซ้ำทุกแถว
- เขียนเพื่อความน่าเชื่อถือระดับสากล เลี่ยงคำที่ทำให้ดูเล็ก เช่น "ระดับมหาวิทยาลัย"
- แสดงตัวเลขเฉพาะที่มีแหล่งอ้างอิง ถ้ายังไม่มีให้ใช้สถานะ pending ของ `StatRow`
- ติดป้าย "ตัวอย่าง" บนรายงานหรือเกมสาธิตที่ไม่ใช่งานจริง
- ติดป้าย "ปิดให้บริการแล้ว" บนผลงานที่ `status` เป็น `closed`

## สี

**กฎงบประมาณสี** ทุกหน้าจอต้องเป็นขาวและเทาเป็นหลัก

- ใช้ `surface` เป็นพื้น และ `text` เป็นตัวอักษรหลัก
- ใช้ `key` กับปุ่มหลักปุ่มเดียวต่อกลุ่ม และ `text-key` กับคำเน้นไม่เกินหนึ่งวลีต่อหัวเรื่อง
- ใช้ `spark` ได้หนึ่งจุดต่อหน้าจอ เช่น วงตา ขีดใต้แท็บที่เลือก หรือปุ่มวงกลมปิดท้าย
- ห้ามปูพื้น section ด้วย `navy` หรือ `gold`
- ใช้ `text-spark` เมื่อต้องเน้นตัวอักษรเล็กบนพื้นขาว ห้ามใช้ `gold` เป็นตัวอักษรบน `white`
- ใช้ `line-control` กับขอบของสิ่งที่กดได้ และ `line` กับเส้นแบ่ง
- ใช้ `signal-*` เฉพาะรายงานและแดชบอร์ด พร้อมคำกำกับทุกครั้ง
- ห้ามเปลี่ยนค่า `navy`, `navy-deep`, `gold`

## ตัวอักษร

- ตั้งหัวเรื่องด้วย family `display` (Bricolage Grotesque สำหรับละติน และ Anuphan สำหรับไทย)
- ตั้งเนื้อหาด้วย `body` (IBM Plex Sans Thai) ที่ line-height 1.75
- ตั้งลำดับ หมวด และคำบรรยายภาพด้วย `mono`
- ใช้ `display-hero` และ `display-xl` กับคำภาษาอังกฤษเท่านั้น
- ห้ามลด letter-spacing บนอักษรไทย และห้ามตั้ง line-height ของอักษรไทยต่ำกว่า 1.15

## การจัดวาง

- ใช้ `space-8` เป็น padding แนวตั้งของ section และ `space-9` ก่อนช่วงไฮไลต์ ถ้าลังเลให้เพิ่มพื้นที่ว่าง
- จัดเป็น 12 คอลัมน์ ผลงานใช้กรอบขนาดเท่ากันทุกชิ้น
- ใช้เส้นบาง `line` แทนการ์ด ไม่มีกรอบ ไม่มีเงา ยกเว้นภาพลอยของ `ServiceIndex`
- ภาพใช้ `radius-none` ปุ่มและภาพในหัวเรื่องใช้ `radius-full`

## รูปทรงประจำแบรนด์

**ดวงตา** คือวงกลมจากตานกฮูกในโลโก้ ใช้แทนตัว O ใน Grow เป็นจุดเริ่มของ `EyeHero` และเป็นปุ่มวงกลมปิดท้ายของ `ContactClose`

## การรองรับทุกหน้าจอ

- นำเสนอบริษัทเป็นทีมจากกรุงเทพที่พร้อมทำงานระดับสากล แสดงที่อยู่เชียงใหม่เฉพาะในฐานะที่อยู่จดทะเบียน
- ทดสอบตั้งแต่ความกว้าง 360px ถึง 2560px และมือถือแนวนอน
- ส่วนเต็มจอใช้ `--edge` เพื่อให้ขอบตรงกับเนื้อหา
- จอเตี้ยกว่า 560px ไม่ตรึงหน้าจอ และแสดงเนื้อหาครบแบบต่อเนื่อง
- สิ่งที่แตะได้บนจอสัมผัสต้องสูงอย่างน้อย 44px

## ลูกเล่นการเลื่อน

มีไว้ให้รู้ว่าเราทำได้ ใช้แค่ 3 แบบนี้

| แบบ | Component | สิ่งที่เกิด |
| --- | --- | --- |
| ตาเปิด | `EyeHero` | ตัว O ขยายเป็นภาพเต็มจอ |
| ข้อความเติมสี | `StatementFill` | คำค่อย ๆ ชัดตามการเลื่อน |
| สามองก์ | `ThreeActs` | ตรึงหน้าจอ เปลี่ยนคำและภาพ 3 ช่วง |

- ใช้ได้หน้าละไม่เกิน 3 ช่วง หน้าย่อยใช้ไม่เกิน 1 ช่วง
- ห้ามหน่วง H1 ห้ามแทรกการเลื่อนของผู้ใช้ และต้องลื่นบนมือถือ
- เมื่อ `prefers-reduced-motion` เปิดอยู่ ให้แสดงเนื้อหาครบแบบไม่ตรึง
- Hover และสถานะปุ่มใช้เวลา 200ms

## ภาพ

- ลำดับการเลือก: ภาพจริงจากงาน, ภาพหน้าจอระบบจริงที่ครอปเท่ากัน, ภาพคอนเซปต์ `Imagery`
- ภาพใน `Imagery` เจนด้วย AI ใช้สร้างบรรยากาศได้ ห้ามใช้แทนผลงานหรือเคสจริง
- กำกับภาพใหม่ด้วยสูตร: ฉากขาวหรือเทาอ่อน พื้นที่ว่างมาก แสงธรรมชาติ และมีจุดทองหรือน้ำเงินจุดเดียว
- ภาพ `Illustrations` และ `Showcase` ชุดเก่าไม่ใช้บนหน้าการตลาด เก็บไว้สำหรับเอกสารและเครื่องมือภายใน

## โลโก้

- ใช้ `OwlLogo` แบบไม่มีคำบรรยาย และ `OwlMark` เมื่อพื้นที่แคบ
- สีโลโก้คือ `text` บนพื้นปกติ และ `white` บนภาพเข้ม
- ห้ามแก้รูปทรงหรือสัดส่วน ห้ามใส่ "THE SOFTWARE HOUSE"

## สถานะและไอคอน

- วงโฟกัสเป็นเส้นทึบ 2px สี `focus-ring` เว้น 3px
- ปุ่ม `key` เมื่อ hover เปลี่ยนเป็น `spark`
- ใช้ `lucide-react` เส้นบาง 1.75 ห้ามใช้อีโมจิแทนไอคอน

ตัวอย่างในระบบนี้เป็น HTML, CSS และ JavaScript สำหรับกำหนดแบบ สัญญา props อยู่ใน `components/index.d.ts`
